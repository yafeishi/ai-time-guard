# 眨眼检测说明

程序通过摄像头观察眼睛轮廓随时间的变化，识别「睁眼 → 闭眼 → 再睁眼」的过程，并据此计数。人脸和眼部轮廓由 macOS 的 Apple Vision 在本机识别，眨眼计数由程序自己的校准和时间规则完成。

## 一次眨眼如何被识别

1. **采集画面。** 使用 macOS AVFoundation 读取摄像头，采样上限约 30 帧／秒。实际帧率受设备和运行负载影响，页面会显示当前值。
2. **定位眼睛。** Apple Vision 找到人脸和左右眼的轮廓点。程序根据轮廓计算每只眼睛的「开口高度 ÷ 眼睛宽度」，并校正人脸框的宽高比例。眼睛越闭合，这个数值通常越小。
3. **分别校准左右眼。** 自然睁眼面对摄像头至少约 5 秒，累计至少 30 个有效样本后，建立个人睁眼基准。采用样本的第 85 百分位值，降低校准期间偶尔眨眼的影响。无需刻意瞪大眼睛；戴眼镜、调整坐姿或改变光线后，可以重新校准。
4. **识别闭合与重新睁开。** 将左右眼当前的开合值分别除以各自的睁眼基准。两眼都明显收窄后，进入闭眼候选状态；随后恢复睁眼且持续时间符合规则，才增加一次计数。闭眼候选状态不会在每一帧重复计数。
5. **跟随自然变化。** 在重新睁眼时，程序用最近的有效样本缓慢更新基准，适应正常睁眼幅度、坐姿和距离的变化。

例如，两只眼睛的相对开合比例从约 `1.0` 降到 `0.3`，随后回升到 `0.9`，程序可能记录为一次眨眼。单独一帧的数值不足以判定，必须结合前后过程。

## 当前版本的判断规则

以下参数用于说明当前实现，不是医学标准，后续算法更新可能调整。

| 项目 | 当前规则 |
| --- | --- |
| 左右眼合并 | 取两只眼睛相对开合比例的较大值，使两眼都收窄时才进入候选状态 |
| 进入闭眼候选 | 合并比例低于睁眼基准的 60% |
| 确认重新睁眼 | 合并比例高于睁眼基准的 75% |
| 闭合时间 | 从进入候选到确认重新睁眼，约 0.025～0.8 秒才计数 |
| 眼部轮廓短暂丢失 | 已进入闭眼候选时，可容忍短暂丢失；超过约 0.25 秒或整张人脸丢失时取消候选 |
| 多人入镜 | 暂停眨眼计数，避免把不同人的眼睛混在一起 |
| 帧率不足 | 实际采样低于约 9.5 帧／秒时暂停眨眼判断 |

闭眼和睁眼使用两个不同阈值，是为了减少数值在一个临界点附近抖动时的重复计数。长时间闭眼、单眼眨动、人脸丢失等情形会受到上述规则限制；这仍是普通摄像头上的估计，并不能保证每次都识别正确。

## 次数、频率和明细的关系

- **即时次数：** 识别到重新睁眼后立即增加；「本次校准后识别」会在重新校准或检测信号重新初始化时清零，已保存的每日总数保留。
- **近期频率：** 在最近 60 秒内，用识别次数除以有效检测秒数，再乘以 60。至少累计 50 秒有效检测且当前检测正常时，才显示频率；准备、校准、眼部不清晰等阶段会显示「观察中」。
- **例子：** 最近窗口内识别 10 次，有效检测 50 秒，显示约 `10 ÷ 50 × 60 = 12 次／分钟`。这是按有效观察时间折算的频率。
- **分钟明细：** 按北京时间的自然分钟保存次数、有效检测时长和当时目标。同一分钟内更改目标时分行；单条有效检测不足 50 秒时保留次数，但不显示频率或判断达标。
- **目标：** 达标只表示频率达到你设置的提醒目标，不代表眼睛健康状况合格。默认目标是可调整的产品设置。

近期频率的 60 秒滑动窗口与明细的自然分钟划分不同，因此两处的数值不一定相同。旧版本仅保存每日汇总，无法还原升级之前的分钟明细。

## 为什么会漏计或多计

光线暗、逆光、眼镜反光、头部转动、眼睛在画面中太小、摄像头帧率下降，都会影响眼部轮廓的稳定性。校准时刻意瞪眼，之后恢复自然状态，也可能让基准不适合当前状态。

如果结果异常，可先恢复正常坐姿与光线，自然睁眼重新校准，再使用「10 秒眨眼对照」：点击后准备 3 秒，以页面倒计时为准计数 10 秒，先填自己数到的次数，再查看机器结果。测试仅统计窗口内开始并结束的眨眼，减少聊天提示延迟和边界动作带来的误差。一次对照一致，不代表所有场景都准确。

本功能提供日常提醒和趋势记录，不用于诊断，也不能确认眼睑是否真正完全闭合或判断干眼等疾病。

## 数据如何处理

- 原始画面只在本机摄像头组件的内存中分析，不保存照片、视频或人脸身份模板。
- 摄像头组件受 macOS 沙箱限制，禁止建立网络连接；主程序通过本机进程管道接收眼部开合程度等数值。
- 页面通过本机 `127.0.0.1` 服务读取状态和统计，不传输原始画面，也不调用云端识别接口。
- 每日汇总保存在 `~/.ai-time-guard/camera-history.json`；分钟明细保存在 `~/.ai-time-guard/blink-history.sqlite3`。
- 最近约 30 秒的逐帧数值诊断和人工／机器对照结果仅在内存保留，退出程序后清除。测试期间实际识别到的眨眼，仍计入日常次数与分钟明细。
